# Прототип веб-сервиса CoreTeams

**Публичная демонстрация:** https://coreteams-epic-25-demo-2026.mariellbnboehmjem96.chatgpt.site

## 1. Назначение

CoreTeams помогает человеку получить готовый результат по своей задаче без самостоятельного поиска и координации отдельных специалистов.

Пользователь общается только с фасилитатором. Фасилитатор уточняет запрос, предлагает варианты там, где пользователь не уверен, собирает подходящую команду ИИ-агентов и понятным языком показывает ход работы.

Прототип демонстрирует основной пользовательский путь эпика 2.5: от первого знакомства с сервисом до принятого результата, доработки и выбора следующего шага.

## 2. Основная ценность

Пользователю не нужно:

- заранее знать, какой специалист ему нужен;
- разбираться в устройстве Core Team Framework;
- самостоятельно составлять техническое задание;
- координировать аналитика, дизайнера, архитектора, разработчика и тестировщика;
- объединять разрозненные материалы команды в итоговый документ.

Сервис сам задаёт наводящие вопросы, объясняет свои решения и выдаёт один общий проверенный результат.

## 3. Пользовательский путь

### Шаг 1. Знакомство с сервисом

Главная страница объясняет, какой результат можно получить, и показывает короткое окно с демонстрацией процесса. Верхняя навигация ведёт на отдельные страницы: «Главная», «Каталог решений» и «Как это работает».

### Шаг 2. Создание проекта

После нажатия «Начать работу» пользователь видит форму регистрации по электронной почте и паролю. В текущем прототипе форма демонстрационная: настоящий аккаунт не создаётся, пароль не сохраняется.

### Шаг 3. Выбор уровня объяснений

Пользователь указывает, насколько подробно и технически сервис должен объяснять ход работы:

- без технических терминов;
- с базовыми понятиями;
- с дополнительными деталями.

Это не проверка знаний. Ответ влияет только на язык объяснений.

### Шаг 4. Диалог с фасилитатором

Фасилитатор последовательно уточняет:

- тип запроса;
- целевую аудиторию;
- ожидаемое изменение или критерий результата.

Пользователь выбирает готовые варианты. Если он не знает ответа, фасилитатор предлагает безопасное предположение и явно отмечает его как предположение, которое нужно подтвердить.

### Шаг 5. Проверка контекста

Когда данных достаточно, фасилитатор показывает сводку:

- что создаём;
- для кого;
- что должно измениться;
- какие предположения сделала команда;
- какие материалы приложены;
- что войдёт в первую версию.

Пользователь может добавить детали или подтвердить переход к первому артефакту.

### Шаг 6. Первый артефакт — лендинг идеи

Сервис формирует наглядный лендинг идеи. Его задача — быстро проверить, одинаково ли пользователь и команда понимают суть будущего результата.

Доступны два действия:

- «Исправить суть» — вернуться к уточнению контекста;
- «Перейти к разработке» — подтвердить идею и перейти к основному этапу.

### Шаг 7. Оценка разработки

Перед запуском сервис показывает:

- доступный лимит внутренних кредитов;
- максимальный резерв на запуск;
- ожидаемый остаток после завершения.

Неиспользованные кредиты должны возвращаться. Модель подписки и пополнения кредитов будет прорабатываться отдельно.

### Шаг 8. Динамическая работа команды

Во время разработки пользователь видит:

- общий процент готовности;
- объяснения фасилитатора;
- подключаемых агентов;
- роль каждого агента;
- причину подключения;
- текущую работу и статус.

Состав команды меняется в зависимости от задачи. В базовом сценарии показаны аналитик, дизайнер, архитектор, разработчик и тестировщик.

Фасилитатор остаётся единой точкой общения и направляет работу агентов. Пользователь не взаимодействует с агентами напрямую.

### Шаг 9. Общий результат

Пользователь получает один итоговый артефакт. Промежуточные документы отдельных агентов не показываются и не требуют ручного объединения.

Результат можно:

- принять;
- отправить на доработку через фасилитатора.

### Шаг 10. Доработка

Пользователь выбирает тип изменения и описывает желаемый результат. Фасилитатор подключает только необходимые роли, запускает новую итерацию и сохраняет предыдущую версию.

### Шаг 11. Следующее действие

После принятия результата доступны два направления:

- масштабировать проект внутри сервиса;
- подготовить проект для привлечения инвестора.

Публичная публикация возможна только после отдельного согласия пользователя на состав публикуемых материалов.

## 4. Материалы и контекст

Кнопка «Материалы» доступна на всех этапах. Пользователь может добавлять файлы и дополнительный контекст до вопросов фасилитатора, во время формирования лендинга, разработки и доработки.

В текущей версии имена выбранных файлов сохраняются только локально в браузере. Файлы не отправляются на сервер.

## 5. Что показывает Core Team Framework

Прототип переводит внутреннюю работу фреймворка на понятный пользователю язык:

- фасилитатор собирает и уточняет контекст;
- оркестрация выбирает нужные роли;
- агенты решают свои части задачи параллельно;
- фасилитатор объясняет, кто подключён и зачем;
- независимая проверка оценивает результат;
- сервис объединяет вклад агентов в один артефакт;
- при доработке запускаются только нужные роли.

## 6. Реализовано в прототипе

- отдельные страницы верхней навигации;
- интерактивный путь от главной страницы до итогового результата;
- демонстрационная регистрация;
- выбор уровня пользователя;
- управляемые вопросы фасилитатора;
- варианты и предположения для ответа «не знаю»;
- сводка собранного контекста;
- лендинг идеи;
- оценка кредитов;
- динамический прогресс и подключение агентов;
- общий результат;
- управляемая доработка и новая версия;
- сценарии масштабирования и привлечения инвестора;
- постоянный доступ к материалам;
- адаптивный интерфейс для настольных и мобильных экранов.

## 7. Ограничения демонстрационной версии

Пока имитируются и требуют дальнейшей разработки:

- настоящая регистрация и авторизация;
- хранение проектов и файлов на сервере;
- реальный запуск команды ИИ-агентов;
- отправка уведомлений по электронной почте;
- биллинг, подписка и пополнение кредитов;
- публикация проекта в каталоге;
- передача материалов инвесторам;
- полноценное версионирование артефактов.

Все действия, связанные с публикацией или передачей данных третьим лицам, в прототипе только объясняются и ничего не отправляют.

## 8. Рекомендуемый сценарий демонстрации

1. На главной странице показать ценность сервиса и окно процесса.
2. Нажать «Начать работу» и пройти демонстрационную регистрацию.
3. Выбрать уровень объяснений без технических терминов.
4. В одном из вопросов выбрать «Пока не знаю», чтобы показать работу с неопределённостью.
5. Проверить сводку и сформировать лендинг идеи.
6. Подтвердить переход к разработке и показать оценку кредитов.
7. Запустить разработку и обратить внимание на объяснения фасилитатора, роли и прогресс.
8. Запросить доработку результата и показать подключение сокращённой команды.
9. Принять результат и показать варианты масштабирования и привлечения инвестора.

## 9. Технический статус

Прототип реализован как интерактивное веб-приложение на HTML, CSS и JavaScript. Локальная серверная часть работает на Node.js. Автоматические проверки изоляции проектов и корректного статуса неизвестного результата проходят успешно.
