# Спецификации эпика 2.5: как читать пакет

Это пакет проектных решений и критериев приёмки, первоначально подготовленный для v3. Формулировки «готово», «согласовано» и описанные серверные гарантии внутри исторических документов нельзя автоматически переносить на v9 или считать подтверждением приёмки заказчиком.

Фактическая реализация текущей версии описана в [архитектуре](../ARCHITECTURE.md) и [README](../README.md).

| Документ | Статус для ревью |
|---|---|
| [2.5-1: доступы](2.5-1-модель-доступов.md) | Предлагаемая модель; серверная авторизация v9 не реализована |
| [2.5-2: состояния](2.5-2-состояния-работы.md) | Контракт Run; локальные состояния UI v9 отличаются |
| [2.5-3: события](2.5-3-журнал-событий.md) | Граница видимых/служебных событий; v9 не получает события API |
| [2.5-4: авторизация](2.5-4-авторизация-и-сессии.md) | Ресёрч и предварительная оценка; требуется подтверждение владельца и Tech Lead |
| [2.5-8: ошибки](2.5-8-безопасные-ошибки.md) | Предлагаемые тексты, не подтверждение обработки всех ошибок исполнителя |
| [2.5-9: границы v1](2.5-9-за-границами-v1.md) | Предлагаемый scope; наличие текста для заказчика не подтверждает отправку |
| [Сводка контрактов](СВОДКА-ЭПИК-2.5-ДОГОВОРЁННОСТИ.md) | Основа сверки с первым направлением; реализация и согласование проверяются отдельно |
| [Исторический статус v3](ЭПИК-2.5-V3.md) | Снимок состояния на 29 сентября, не отчёт о готовности v9 |

Перед закрытием задач: подтвердить требования у владельцев, сопоставить каждое с проверяемым результатом и отдельно отметить «спецификация / прототип / интеграция». Демонстрационный подбор предметных ролей в v9 не означает реализацию пользовательских ролей во фреймворке.
