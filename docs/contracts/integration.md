# Порядок подключения и передачи между направлениями

Статус: **план проверки, не подтверждение готовой интеграции**.
Существующие документы и версии: [реестр](README.md).

## Границы

```text
React B --> gateway <--- outbound WS --- runner
               |
               +--> storage adapter --> central bytes + metadata
```

Браузер не обращается напрямую к runner/storage. Transport journal gateway не
заменяет хранилище артефактов. Доступ к checkpoint bytes и авторизация чтения —
отдельные реальные интеграционные обязанности, а не следствие наличия metadata.

## 1. Закрепить проверяемый набор

Дима и Филипп фиксируют фактический manifest перед прогоном. Не слепо смешивать
все ветки: совместимость выбранных ревизий ещё предстоит подтвердить.

| Компонент | Полный commit SHA | Роль / базовая ветка | Проверка и результат |
|---|---|---|---|
| WEB B | NOT_PROVIDED | PR #11 candidate ce8b6f4; записать реально собранный SHA | NOT_RUN |
| Gateway / browser mapping | NOT_PROVIDED | реализация Димы + выбранный receiver | NOT_RUN |
| Runner | NOT_PROVIDED | PR #10 / input-usage / fork fixes — указать состав | NOT_RUN |
| Storage / migrations | NOT_PROVIDED | реализация Арины, не только ADR | NOT_RUN |
| Runtime / compose | NOT_PROVIDED | конфигурация Филиппа, версия/образ/digest | NOT_RUN |

Не заменять NOT_PROVIDED названием ветки, «последнее» или успешным статусом.
Новый manifest при изменении любого компонента; результат старого прогона к нему
автоматически не переносится.

## 2. Арина → Дима и Филипп: storage handoff

- [ ] Диме: одна закреплённая версия существующего write/read API, поля/типы/
  обязательность, примеры запросов/ответов, errors и retry/conflict semantics.
- [ ] Bytes именно immutable checkpoint: hash, размер, безопасный path, IDs проекта,
  Run, документа, версии и операции; что гарантирует durable receipt.
- [ ] Отдельные readback/download/approval, запрет чужих project/artifact IDs.
- [ ] Филиппу: миграции, переменные/точки подключения без значений секретов,
  persistent volumes, права и инструкция restart/recovery.
- [ ] Подключить готовые ZIP builder/validator; заново их не писать.
- [ ] Закрыть/перепроверить S-01–S-04 по [verification](verification.md).

## 3. Дима + Филипп: runner ↔ gateway

Использовать [готовый receiver candidate и его команды запуска](https://github.com/AcryCxde/PP-Sber-Autumn-2026/blob/cd6a51fefd456a3e50f068cc29ac55b21ff137cc/docs/2.4/gateway-receiver.md).
Он требует включения в настоящий gateway; не является заменой browser API.

- [ ] Auth, hello/welcome, journal replay, event_id dedup, command/ack, heartbeat.
- [ ] Структурный вопрос → ответ → продолжение того же Run.
- [ ] Не отбрасывать usage/question/role/artifact события при проекции для WEB.
- [ ] Gateway получает/сохраняет bytes через storage; completed не выдаётся вместо
  неподтверждённой записи, поздний confirm не переоткрывает terminal Run.
- [ ] Реальный restart/reconnect без повторного выполнения принятой команды.

## 4. Дима → Катя: browser API для React B

Нужны URL/base API и точный SHA, безопасная инструкция доступа и закреплённый
контракт: команды/ответы/events или snapshots, IDs/revision, questions/answers,
upload, сохранение/версии/approval, download/ZIP/read/reopen и ошибки.
Отдельно зафиксировать cookie/session/ownership и CORS/CSRF для выбранного origin.
Секреты не помещать в чат, документацию или VITE bundle.

Минимальная связка с техническим чатом может быть полезна как smoke, но это не
проверка React B из PR #11. Явно указать, какой WEB использован, и не объявлять
успех B без прогона B. Маршруты B пока proposal: согласовать mapping, а не молча
навязать gateway новый независимый API.

## 5. Проверка B и общего стенда

Катя проверяет B после передачи API; Филипп организует общий технический прогон,
Дима/Арина исправляют свои границы. Использовать [чеклист и протокол](verification.md).
При блокере записать шаг/ошибку/SHA и действие, не создавать вторую реализацию.
Новый срок требует подтверждения исполнителя; обещания «за два часа» здесь нет.

## Что значит «без дублей»

Это **не запрет Диме пользоваться своим агентом** и не утверждение о дублировании
чьей-то работы. Повтор HTTP/WS после потери ответа должен ссылаться на ту же
операцию/команду. Он не должен запускать второй Run, модель или сохранение версии.
Повтор прежнего ключа с изменённым телом должен давать согласованный конфликт,
а не исполняться как новая операция. Явная доработка после completed, наоборот,
создаёт новый связанный Run. Transport ack, durable artifact receipt и пользовательское
одобрение — три разных подтверждения; один нельзя выдавать за другой.

## Merge gate

Дима — технический merge-owner; Филипп подтверждает сборку/прогон и откат,
Арина — хранение, Катя — пользовательский путь и отдельный ОК конкретным PR.
Этот draft ничего не сливает и не включает auto-merge. PR #11 остаётся draft.
Порядок фактических merge определяется зависимостями проверенного manifest,
не календарным окном и не наличием mergeable:true у отдельных PR.
