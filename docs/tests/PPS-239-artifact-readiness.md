### Критерии пригодности

Артефакт получает статус **Pass**, только если выполнены все обязательные пункты:

- [ ] Файл существует в зафиксированном пути workspace и имеет ожидаемое расширение.
- [ ] Файл непустой и полностью декодируется как UTF-8.
- [ ] CSV синтаксически читается либо JSON синтаксически валиден.
- [ ] Присутствуют все согласованные обязательные колонки/ключи.
- [ ] Нет битых строк, лишних/утраченных CSV-полей, дублирующихся/пустых заголовков.
- [ ] Нет `NaN`; для JSON также нет `null`, `Infinity` и `-Infinity`.

## 3. Использование валидатора

Требуется только Python 3.11+ и стандартная библиотека.

Первичная проверка и фиксация контрольного состояния:

```powershell
python .\artifact_validator.py .\workspace\result.csv `
  --run-id "run-001" `
  --required-fields "id,name,status" `
  --phase "первичный прогон" `
  --persistence snapshot
```

После паузы или перезапуска контейнера/процесса:

```powershell
python .\artifact_validator.py .\workspace\result.csv `
  --run-id "run-001" `
  --required-fields "id,name,status" `
  --phase "повторное открытие после паузы" `
  --persistence verify
```

Полезные параметры:

- `--log PATH` — иной путь Markdown-журнала;
- `--snapshot-file PATH` — иной путь JSON-снимка контрольного состояния;
- `--persistence none` — только валидация и журналирование;
- код возврата `0` означает Pass, `1` — Fail.

Проверка персистентности выполняется двумя отдельными запусками. Между `snapshot` и `verify` нужно реально выполнить предусмотренную кейсом паузу/перезапуск. Скрипт подтверждает неизменность файла, но ручное открытие в целевом ПО фиксируется отдельно в журнале.
