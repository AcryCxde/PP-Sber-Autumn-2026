## 1. Вердикт

**Нужны правки. Прямая интеграция PR #11 с runner/gateway сейчас заблокирована двумя разрывами на стороне gateway и CTF (B-1, B-2 ниже).**

Обоснование:

- Сам PR #11 выключен по умолчанию (`VITE_CTF_V2_ENABLED`), помечает контракт V2 как «proposed, NOT approved» и не претендует на живую интеграцию (`verification.md`: «No live CTF, real extraction, role assignment, server storage… verified»). Мерджить его как кандидата интерфейса можно; блокера в самом PR нет.
- Контракт V2 — REST поверх `projects/{id}/…`. У gateway из master и у runner другой контур: WebSocket `run.create`/`run.subscribe` для браузера (`backend/main.py:699-826`) и лента `events.v0` (`docs/contracts/events-v0.md`). Адаптера нет, контракт V2 с `events.v0` не сверен: часть сущностей V2 (проект, файл с байтами и hash, этап, документ+версия, approve, ZIP, usage, снимок Run с `revision`) в `events.v0` отсутствует.
- Блокер B-1: в `backend/` нет эндпоинта для runner (WebSocket с `hello`/`welcome`, приём `event`, отправка `command`). Gateway из master сам запускает `claude` как подпроцесс (`backend/main.py:76-96`), а не управляет runner-контейнером. Требования раздела 11 `events-v0.md` не выполнены ни в одном пункте. Поэтому путь start → вопрос/ответ того же Run через настоящий gateway сегодня пройти нельзя; runner проверен только фейковым gateway (`runner/evals/fake_gateway.py`).
- Блокер B-2: у runner нет входов, которые V2 считает обязательными: файлы с байтами и hash, выбранные роли и этапы, ссылка на версию при доработке, approve. Команды runner — только `message`, `fork_answer`, `stop` (`runner/src/ctrunner/protocol.py:88-96`).
- Что уже совпадает по смыслу: вопрос фасилитатора и ответ в том же Run (`facilitator.question` → `user.answer.accepted`, один `run.started`; `runner/evals/test_question.py:62-64`), повтор вопроса после `docker kill` (`test_question.py:69-94`), явные исходы `run.failed` / `run.outcome_unknown` без подмены успехом (`events-v0.md` §3-4), идемпотентность команд по `id`, отсутствие процентов и ETA.

## 4. Топ разрывов (по влиянию на PPS-138)

1. **B-1 (пункт 17).** У gateway нет эндпоинта для runner. Без него «живой Run через gateway» невозможен; всё остальное можно проверять только фейком.
2. **B-2 (пункты 1-3).** Нет входа файлов, ролей и этапов в runner; V2 считает их ядром запуска.
3. **Доработка = новый Run (пункт 6).** Модель Run у web и у runner расходится; решение нужно до реализации REST-адаптера.
