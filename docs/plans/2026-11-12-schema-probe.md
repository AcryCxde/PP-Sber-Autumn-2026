# PostgreSQL schema probe v1 — Implementation Plan

> **For the implementer:** Use `skill-issue:executing-plans` task-by-task. This document is a plan, not execution authorization for production.

**Goal:** Block risky image deployment unless a bounded live PG16 catalog snapshot equals the reviewed canonical baseline of the exact release SHA.
**Architecture:** One installed SQL SELECT captures supported inventory and unsupported-class evidence in one READ COMMITTED snapshot. Pure Python validates/canonicalizes it; a bounded asyncpg shell checks server-owned mapping, expected baseline and clearance before returning existing `SchemaEvidence`. Keep `deploy()` lock, verifier and patch ordering intact.
**Stack:** Python 3.12, existing asyncpg/SQLAlchemy/Alembic dependencies, pytest; owned disposable PostgreSQL 16.15. No new DB library or application startup imports in the provider.
**Approval:** User approved local implementation/disposable tests and the narrow SERIAL amendment on 2026-11-12; [approved design](2026-11-12-schema-probe-design.md) is normative.
**Constraints:** Only local work; preserve unrelated dirty worktree changes. No SSH/live DB/VM changes, GitHub mutations, A/P activation, commit/push, root uv.lock, builds/model calls. Plan first; do not execute code changes in the planning session.
**Non-goals:** Data correctness, backup/restore/RPO proof, migration execution on target, broad PostgreSQL support, all-deploy drift checks, UI allowlist changes, SDK/runner redesign.

## Fixed v1 contract (implement before publishing evidence)

- `schema_probe.py`: frozen validated `Profile`, `TargetMapping`, `Baseline`; `ProbeError(ValueError)` with sanitized fixed messages and chained causes. New `canonical_signature(snapshot: object, profile: Profile) -> str`, `async read_catalog(mapping: TargetMapping) -> object`, `probe(mapping: TargetMapping, baseline: Baseline, clearance: Clearance, release_sha: str) -> SchemaEvidence`.
- Profile binds `pg_catalog_v1`, `server_version_num=160015`, SQL file SHA256, fixed deparse settings and inventory version; never silently accept another minor or query revision. Canonical JSON uses UTF-8, sorted mapping keys, compact separators, no NaN/duplicate fields; named identities are component arrays, not concatenated delimiter strings. Sort unordered objects; retain column/key/include order. Prefix signature `pg_catalog_v1:sha256:`; no OID in portable JSON.
- Snapshot shape: exact keys `profile, facts, inventory, unsupported, counts`; facts include database/current+session user/server version/address/port. Inventory has schemas/tables/columns/constraints/indexes/sequences and stable dependency edges; counts must agree with complete arrays. No LIMIT, paging, per-table SELECT, information_schema visibility filter or swallowed deparse error. Application rows/Alembic contents excluded; `alembic_version` table structure included.
- One SQL CTE statement explicitly checks these closed catalog classes: `pg_namespace,pg_class,pg_attribute,pg_attrdef,pg_type,pg_constraint,pg_index,pg_am,pg_opclass,pg_opfamily,pg_collation,pg_inherits,pg_partitioned_table,pg_sequence,pg_depend,pg_extension,pg_proc,pg_trigger,pg_rewrite,pg_policy,pg_publication,pg_publication_rel,pg_publication_namespace,pg_subscription,pg_subscription_rel,pg_event_trigger,pg_foreign_table,pg_foreign_server,pg_foreign_data_wrapper,pg_user_mapping,pg_conversion,pg_operator,pg_cast,pg_transform,pg_language,pg_ts_config,pg_ts_config_map,pg_ts_dict,pg_ts_parser,pg_ts_template,pg_statistic_ext,pg_default_acl,pg_init_privs,pg_shdepend,pg_database,pg_authid,pg_auth_members`.
- For restricted catalogs use documented accessible views/functions/column grants only if tests prove equal detection; e.g. use `pg_roles` rather than secrets in `pg_authid`. Record each capability explicitly; unavailable required coverage blocks activation. Never SELECT password/subconninfo. Dependencies into/out of scoped objects and extra user schemas must be audited, not merely objects matching baseline names.
- Table/type/constraint/index details follow design lines 34–44: permanent heaps/built-in types only, exact typmods/defaults/collations; PK/UNIQUE/FK/CHECK attributes and ordered references; btree expression/predicate/include/opclass/nulls/sort/options and valid/ready/live flags. Unknown options/classes fail closed. All user schemas enumerated, including no-USAGE schemas. Exempt only verified system inventory, standard plpgsql extension members, derived row/array types, FK triggers and TOAST of supported objects; no blanket `pg_*` name or extension exemption.
- SERIAL only: sequence identity+definition (type/start/increment/min/max/cache/cycle), owning table/column dependency `a`, exact default `nextval` and its dependency to that same sequence. No sequence relation reads, current value/is_called or raw OID; standalone/custom, identity (`i`) and generated reject. Ownership here means OWNED BY column dependency, not role owner/ACL fingerprint. Grants/owners checked separately.
- Reject views/materialized/foreign/partition/unlogged/temp/inheritance, custom types/domains/collations, user functions/procedures/triggers/rules/RLS/policies, extensions other than reviewed plpgsql, publication/subscription/event triggers/foreign servers and other user objects in the declared classes. Make exclusions and dependency exceptions explicit and reviewable; no claim of universal unknown-object detection.
- Transaction: direct connection ≤5s, READ COMMITTED + BEGIN READ ONLY, SET LOCAL search_path=pg_catalog, standard_conforming_strings=on, TimeZone=UTC, DateStyle=ISO/YMD, IntervalStyle=postgres, extra_float_digits=3; lock_timeout=1s, statement_timeout=5s. One catalog SELECT; transaction-control/settings are not extra inventory reads. Overall wall budget ≤15s including connect/cancel/close; result ≤4MiB encoded UTF-8. SQL returns bounded overflow sentinel instead of oversized inventory; Python independently checks bound. No truncated successful evidence, weaker retry, isolation exception or `nextval` invocation.
- Protected proposed fixed paths: `/etc/coreteams-deploy/schema-probe.json`, `schema-baseline.json`, `schema-probe-credential.json`; no client paths/imports/DSN. Config keys exactly `schema,endpoint,port,ca_file,cluster_identity,database,role,schemas,profile`; credential keys `username,password`; baseline keys `schema,release_sha,profile,schemas,expected_signature,target_mapping_hash,clean_signature,upgrade_signatures,migration_head`. Strict bounded duplicate-key rejecting parsing; config/baseline ≤64KiB, credential ≤16KiB. CA path absolute from protected config only, parent checks too.
- Baseline `schema=1`, immutable SHA (40 nonzero hex), head `20261111_0005`, exact profile, equal clean/upgrade signatures. `target_mapping_hash` binds reviewed endpoint/TLS/cluster/database/role/schema/profile. Returned target hashes mapping plus verified connection facts, ≤512 chars; expected clearance target must match it. Clearance SHA/signature must equal baseline SHA/expected signature BEFORE connecting; live must then equal expected. Copying live hash cannot bless drift.
