# CI/CD Implementation Plan

> **For the implementer:** использовать `skill-issue:executing-plans`, выполнять по одной задаче.
> Текущий этап — planning. Локальная реализация допустима исходной задачей после handoff в executing-plans;
> GitHub/VM activation, первый production переход и commit/push требуют отдельных разрешений.

**Goal:** PR required build/tests/linters → squash master → проверенные immutable release images → ручной deploy в k3s.
**Architecture:** GitHub Actions build/check/publish; отдельный dispatch Deploy; GHCR digest pulls через
существующий k3s/containerd; restricted SSH wrapper с server-side lock. Сохранить `EXECUTOR=cli`.
**Tech stack:** GitHub Actions YAML, Docker/BuildKit, Python contract tests, shell, GHCR, Kubernetes.
**Constraints:** [дизайн](2026-11-11-cicd-design.md) — нормативный contract; secrets не сохранять.
**Non-goals:** UI, GitOps, перенос на Docker/runner, прикладной рефакторинг, автоматическая миграция/restore.

## Порядок разрешений и изоляция

- **Текущая planning-подзадача:** только эти документы в текущем worktree; не checkout/switch/stash/commit/push/SSH mutations.
- **Этап L, local implementation после handoff executing-plans:** будущий CI/CD worktree от проверенного live master,
  без prototype commits. Дополнительное разрешение L не требуется; CI можно реализовать, пока production blockers закрыты.
- **Этап A, отдельное подтверждение GitHub/VM activation:** settings, branch protection, secrets,
  создание package/publish (включая private upload), SSH identity/RBAC/pull credentials. Не подразумевается L.
- **Этап P, отдельное подтверждение первого production перехода:** maintenance, data changes и первый deploy
  только после успешного rehearsal. Не подразумевается A или согласованием дизайна.
- Оба plan docs игнорируются правилом `.gitignore:12` (`plans/`), а не просто untracked.
  Ignore сейчас не менять. Только в будущем разрешённом commit добавить именно их через
  `git add -f -- docs/plans/2026-11-11-cicd-design.md docs/plans/2026-11-11-cicd.md`.
- Будущие commit/push/PR/merge разрешаются отдельно; план их не выполняет. При открытии PR нужен code-review
  и русскоязычный отчёт в PR до слияния, только после разрешения GitHub mutations.
