# PP-Sber-Autumn-2026 · CoreTeams

## Новый прототип направления 2.5

**Опишите сложную задачу по продукту — получите решение, которое можно проверить.** В новом локальном прототипе CoreTeams уточняет вводные в диалоге, предлагает состав команды и план работы, затем собирает единый результат: основания, допущения, карту гипотез и первый шаг. Результат можно открыть отдельным окном, скачать в выбранном формате и доработать при изменении условий.

Для каждого нового проекта в прототипе человек выбирает одну из двух ролей:

- **Владелец решения** — руководитель или инициатор, которому нужно выбрать и обосновать решение по продукту.
- **Ответственный за реализацию** — исполнитель, которому нужно проверить технический вариант. Дополнительно он может получить черновик скилла с `SKILL.md` для повторного применения.

- [Рабочее пространство на React: запуск и проверенный сценарий](web-product/prototypes/2026-11-11/README.md)
- [Автономный HTML для просмотра без сборки](web-product/prototypes/2026-11-11/reference.html)
- [Бизнес-логика и задачи реализации сервиса](docs/2.5/coreteams-product-web-implementation-2026-11-11.md)

В этом прототипе проекты и версии хранятся в браузере. Регистрация, работа агентов, анализ файлов и серверное сохранение показаны как будущие возможности и не выполняются. Отдельный демонстрационный стенд со сквозным сценарием не подключён к этой версии интерфейса. Прототип не заменяет основной интерфейс и runtime из master.

## Рабочее пространство web-product

[web-product](web-product/README.md) — интерфейс CoreTeams v9.2 (кандидат B), подключённый к backend через контракт V2 (`/api/v2`, реализация — `backend/api/product.py`). Основной интерфейс — CoreTeams из `frontend/` с отдельными страницами (`#home`, `#catalog`, `#profile`, `#project/…`, свободный чат `#chat`); в docker-стеке он открывается на `/`. Рабочее пространство web-product и панель администратора доступны на `/product/` с той же сессией. Проекты из основного интерфейса web-product показывает в разделе «Проекты из прежнего интерфейса» только для чтения.

## Файлы, созданные агентом

Исходные байты каждого файла, который агент создал или изменил за время работы (через Write или скриптом, включая docx, xlsx, pdf и картинки), backend кладёт в S3-совместимое хранилище — в docker-стеке это SeaweedFS (сервис `s3`, ключи `S3_ACCESS_KEY`/`S3_SECRET_KEY` в `.env`). В базе остаются путь, sha256, тип и текстовое превью. Скачать файл можно в рабочем пространстве (кнопка «Скачать файл» у версии), в свободном чате и через `GET /api/runs/{run_id}/events/{seq}/file`. Без `S3_ENDPOINT_URL` хранилище выключено: текстовые файлы скачиваются из базы, бинарные — нет.
