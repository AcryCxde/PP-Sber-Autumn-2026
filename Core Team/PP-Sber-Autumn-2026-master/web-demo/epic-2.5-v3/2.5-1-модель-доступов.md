# 2.5-1. Модель доступов

## Роли

| Возможность | Гость | Пользователь | Администратор |
|---|---:|---:|---:|
| Открыть главную, описание сервиса и публичный каталог | Да | Да | Да |
| Зарегистрироваться и войти | Да | — | — |
| Смотреть список проектов | Нет | Только свои и предоставленные | Все — только для администрирования |
| Создавать проект | Нет | Да, в пределах лимита | Да |
| Читать и менять контекст проекта | Нет | Только при доступе к проекту | Только при обоснованной поддержке и с аудитом |
| Загружать и скачивать материалы | Нет | Только в доступном проекте | Не получает содержимое по умолчанию |
| Запускать, повторять и отменять Run | Нет | Только в доступном проекте | Может остановить опасный/зависший Run |
| Читать пользовательский журнал событий | Нет | Только в доступном проекте | Да, без секретов и скрытых рассуждений |
| Скачать подтверждённый артефакт | Нет | Только из доступного проекта | Только при обоснованной поддержке и с аудитом |
| Управлять пользователями, блокировками и лимитами | Нет | Нет | Да |
| Смотреть техническую диагностику | Нет | Нет | В отдельном служебном контуре |

## Правила проверки

1. Право проверяет сервер для каждого `projectId`, `runId`, `eventId`, `materialId` и `artifactId`.
2. Идентификатор из URL или браузера не является доказательством доступа.
3. Администратор не получает неограниченный доступ к содержимому клиентских проектов по умолчанию.
4. Служебные действия администратора записываются в аудит.
5. Гостевой доступ не создаёт проект и не принимает пользовательские файлы.
6. Для первой версии совместное редактирование и выдача доступа другим пользователям не реализуются.

## Статус для демо

В прототипе показаны гостевые страницы и профиль пользователя. Серверный тест запрещает доступ второго демо-пользователя к чужому проекту. Полноценная RBAC и администраторский интерфейс остаются за границами этапа A.
