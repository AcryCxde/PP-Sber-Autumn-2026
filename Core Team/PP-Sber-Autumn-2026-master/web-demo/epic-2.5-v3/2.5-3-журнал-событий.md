# 2.5-3. Журнал событий

## Пользовательские события

| Событие | Видимость | Пользовательский текст |
|---|---|---|
| `run_queued` | Видно | Работа поставлена в очередь |
| `run_started` | Видно | Команда начала работу |
| `progress` | Видно после нормализации | Методист проверяет связь целей и заданий |
| `waiting_for_input` | Видно | Нужен ваш ответ, чтобы продолжить |
| `material_received` | Видно | Материал добавлен в проект |
| `artifact_proposed` | Видно | Черновик результата готов к проверке |
| `artifact_saved` | Видно | Версия результата сохранена |
| `completed` | Видно | Работа завершена |
| `failed` | Видно безопасное сообщение | Работу не удалось завершить; данные проекта сохранены |
| `unknown` | Видно | Результат запуска пока не подтверждён |
| `limit_reached` | Видно | Лимита недостаточно; запуск не начался |

## Служебные события и данные

| Данные | Видимость |
|---|---|
| Shell-команды, stdout/stderr и stack trace | Скрыто |
| Скрытые рассуждения модели и внутренние черновики | Скрыто |
| Секреты, токены, заголовки авторизации | Скрыто и маскируется в служебных логах |
| Пути файловой системы, container ID, host/IP | Скрыто |
| Сырой token stream модели | Скрыто |
| Внутренние повторные попытки и heartbeat | Скрыто, если не влияют на пользователя |
| Детальная стоимость каждого внутреннего вызова | Скрыто; пользователю показывается агрегированный резерв/расход |
| Диагностический код ошибки | Только служебный контур; пользователю — корреляционный номер при необходимости поддержки |

## Контракт публичного события

Каждое событие содержит неизменяемый `eventId`, `projectId`, `runId`, порядковый `sequence`, время `createdAt`, безопасный `type` и нормализованный `payload`. Дубликаты исключаются по `eventId` и `sequence`.
